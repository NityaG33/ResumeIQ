# ResumeIQ — AI Resume Intelligence Platform

ResumeIQ is a full-stack **AI-powered Resume Intelligence Platform** that helps candidates understand the quality of their resume, evaluate ATS friendliness, and measure how well their resume matches a specific job description.

The platform combines **rule-based resume analysis, NLP techniques, semantic embeddings, TF-IDF similarity, skill matching, and role alignment** to generate an explainable resume and job-match report.

Analyze a resume for:

### 🎯 Resume–Job Description Matching

Compare a resume against a job description using a hybrid scoring approach:

- **Skill Coverage**
- **Semantic Embedding Similarity**
- **TF-IDF Similarity**
- **Role Alignment**

The final score is calculated using:

| Component | Weight |
|---|---:|
| Skill Coverage | 50% |
| Semantic Embedding Similarity | 30% |
| TF-IDF Similarity | 10% |
| Role Alignment | 10% |
| **Total** | **100%** |

This approach combines explicit skill matching with both lexical and semantic text similarity.

## 🧠 How the Matching System Works

ResumeIQ uses multiple independent signals instead of relying on a single similarity algorithm.

### 1. Skill Coverage

The system extracts relevant skills from the resume and job description and compares them.

For example:

```text
Job Description:
Python, FastAPI, MongoDB, Docker, AWS

Resume:
Python, FastAPI, MongoDB, Docker
```

Skill coverage:

```text
4 / 5 = 80%
```

---

### 2. Semantic Embeddings

ResumeIQ uses the pretrained:

```text
all-MiniLM-L6-v2
```

Sentence Transformer model.

The resume and job description are converted into vector representations, and **cosine similarity** is used to measure semantic similarity.

This helps identify similar meaning even when the exact words differ.

Example:

```text
"Develop REST APIs"

≈

"Build web services"
```

---

### 3. TF-IDF Similarity

TF-IDF provides a lexical similarity signal based on the importance and overlap of words.

It helps capture cases where the resume and job description use similar terminology.

Example:

```text
JD:
Python FastAPI backend developer

Resume:
Python FastAPI backend engineer
```

The significant word overlap produces a higher TF-IDF similarity.

---

### 4. Role Alignment

ResumeIQ also evaluates how well the resume aligns with the selected role.

Supported roles include:

- Backend Developer
- Frontend Developer
- Software Engineer
- ML Engineer

Role profiles provide expected skills and characteristics for each role.

## 📐 Resume Quality Scoring

Resume quality is primarily **rule-based**, rather than being generated by a machine-learning model.

The system analyzes signals such as:

- Section presence
- Contact information
- Quantified achievements
- Action verbs
- Bullet points
- Resume length
- ATS-friendly structure

The overall resume score is divided into:

| Category | Maximum Score |
|---|---:|
| Structure | 30 |
| Contact Information | 15 |
| Content | 40 |
| ATS | 15 |
| **Total** | **100** |

The system then maps the score to a grade and generates recommendations based on detected weaknesses.

## 📊 Example Match Score

Suppose a resume produces:

```text
Skill Coverage          82%
Embedding Similarity    75%
TF-IDF Similarity       68%
Role Alignment          80%
```

The final score is calculated using:

```text
(82 × 0.50)
+ (75 × 0.30)
+ (68 × 0.10)
+ (80 × 0.10)
```

Result:

```text
78.9 / 100
```

The system then classifies the match using rule-based confidence thresholds.

## 💡 Why a Hybrid Matching Approach?

A single similarity technique has limitations.

### Skill Coverage

Good for identifying explicit technical requirements.

### TF-IDF

Good for measuring lexical/keyword overlap.

### Semantic Embeddings

Good for understanding similarity in meaning.

### Role Alignment

Adds role-specific context.

Combining these signals provides a more useful and explainable result than relying on only keyword matching or only semantic similarity.

### Explainability

### User-Specific Data

## ⚠️ Current Limitations

ResumeIQ is a rule-based and hybrid NLP system rather than a fully trained end-to-end recruitment model.

Some limitations include:

- Skill extraction depends on predefined skill dictionaries and aliases.
- Resume quality analysis relies heavily on predefined rules and thresholds.
- Semantic similarity does not guarantee that a candidate actually possesses a skill.
- TF-IDF focuses on lexical similarity rather than deeper meaning.
- The system is intended as a resume-analysis and decision-support tool, not an automated hiring decision system.
- The current authentication implementation uses access-token JWT authentication without a refresh-token workflow.
